# 天打雷劈 · ¡Cuidado con el rayo!

中文讀音打字遊戲（給西語學生）。看到一個字，在時間內用內建的拼音或注音鍵盤打出讀音（要打聲調）。
打對往上走一階；打錯或時間到，被雷劈一次，但還是往上走。從最底下一路爬到頂，看被劈幾次；**題數可選 10／15／20／25 題（階梯數＝題數）**。

- 網址：https://wangchiapin.github.io/Cuidado-con-el-rayo/
- `index.html` ＋ `bg/` 資料夾（7 個場景 × 4 種題數 ＝ 28 張長背景 webp 圖片檔，要一起放上去；遊戲一局只載入那一種題數的 7 張），直接用 GitHub Pages 開（Settings → Pages → main / root）。
- **遊戲畫面是直式滿版**：背景圖鋪滿整個手機畫面；人物一開始站在整段階梯的**最底下**（階梯下面是平地），**鏡頭跟著人物往上捲**（人物固定站在作答欄上方），快到終點時圖頂到底，人物就換成往上走到頂端的建築；出題時，題目、輸入區和鍵盤會從底部滑上來；打完（或時間到）面板滑下去，露出滿版畫面看人物上樓或被雷劈；下一題再滑上來。答對／答錯的提示文字浮在畫面上方。連線時被淘汰的人和觀賽的人看到的是沒有面板的滿版畫面。
- 介面可切換：繁體／簡體、中文／西文／英文。拼音鍵盤、注音鍵盤都有（電腦也能直接用實體鍵盤打）。
- 首頁很簡單（電腦版標題和圖片放大、圖片高度跟著視窗；手機版圖片會填滿中間空白）：最上面是標題和副標「念對就向上，念錯就雷劈」，下面是一張放大的場景圖（人物站在階梯上）、一個名字欄（Tu nombre），名字欄下面是 男生／女生 兩個選項，最底下是 開始 鈕（電腦版不會拉太寬）。電腦版版面依視窗高度算好，整個首頁不用捲動。**開始鈕下面一排五個圖示，由左到右是：連線（方框）、🏆 排行榜（方框）、⚙ 設定**（字形、介面語言、鍵盤、難度、題數）、**❓ 遊戲說明、🔊 靜音**（首頁的 🔊 和遊戲裡右上角的 🔊 是同一個開關）。標題「天打雷劈」左邊是一道閃電、右邊是被雷擊的小人（都是自己畫的向量圖，不是 emoji）。矮視窗和小手機會自動縮小標題、拿掉副標的西文行，整頁仍然不用捲動。人物每次回首頁、每次再玩都會隨機換一個（男生或女生在名字欄下面選）。

## 難度

三種難度，差別在「題庫範圍」和「每題時間」。字的等級用「華語八千詞」：N1、N2 = 準備級，L1 入門、L2 基礎、L3 進階、L4 高階、L5 流利（數字越大越難）。

| 難度 | 每題時間 | 字的範圍 | 字數 |
|---|---|---|---|
| 簡單 | 15 秒 | N1、N2、L1 | 355 |
| 普通 | 10 秒 | N2、L1、L2、L3 | 598 |
| 進階 | 10 秒 | L2、L3、L4、L5，加上輕聲字（的、嗎、吧…） | 1,021 |

輕聲字只在進階出現。一局的階數＝你選的題數（10／15／20／25，在 ⚙ 設定裡選，預設 10），每階一個字。星星照比例：沒被劈 3 顆，被劈次數 ≤ 題數的 20% 2 顆，≤ 50% 1 顆，更多 0 顆（10 題：1～2 次 2 顆、3～5 次 1 顆、6 次以上 0 顆；15 題：≤3、≤7；20 題：≤4、≤10；25 題：≤5、≤12）。

## 排行榜（Firebase）

- 開始前一定要先在首頁輸入名字（沒填按開始會提示、不會開始；最多 14 個字，存在自己的手機裡）；🏆 鈕看排行榜。
- **每種題數（10／15／20／25）× 每個難度（簡單／普通／進階）各一個榜，共 12 個**，拼音和注音玩家在同一個榜（鍵盤只是輸入方式，題目一樣難）；題數不同不能比，所以分開。榜單視窗上面一排選題數、下面一排選難度。
- 排名：**被雷劈越少越前面，一樣就比誰爬得快**。只顯示前 10 名，自己那一列會標色。
- 每台裝置（匿名登入）每個榜只留一筆最好成績；比較差的成績不會蓋掉好的。
- 結算時自動上榜（成績沒有比自己以前好就不會蓋掉）；因為開始前一定有名字，結算畫面不再有名字欄和「上榜」鈕。
- 讀不到榜單時，遊戲照常玩，只是榜單區顯示「暫時無法使用」。
- Firebase 專案：`memorma-24dab`（跟翻牌記憶、收納小達人等同一個）。
- 資料位置：`rayo_boards/{榜名}/entries/{匿名登入的 uid}`，榜名：10 題沿用舊榜 `easy`／`normal`／`hard`，其他題數是 `難度_題數`（例如 `normal_15`、`hard_25`）
  - 欄位：`name`、`strikes`（被劈次數 0～題數）、`secs`（用時秒數）、`kb`（`pinyin`／`zhuyin`）、`rank`、`updatedAt`
  - `rank = (題數 − 被劈次數) × 100000 + (99999 − 用時秒數)`，越大越前面。
  - 本機最佳紀錄：10 題沿用 `typingRayo.best.難度.鍵盤`，其他題數多一段 `.題數`。
- **安全規則**：完整版在 `firestore.rules.txt`（是 memorma 現行規則加上這個遊戲的 `rayo_boards`（排行榜）和 `rayo_rooms`（連線房間）兩個區塊，其他一個字都沒動）。要上線時，把整份貼到 Firebase 主控台 → Firestore → 規則 → 發布。也請把同一份蓋到 Memorama repo 的 `firestore-rules-full.txt`，才不會下次改規則時把這一段弄丟。

## 連線模式（最多 15 人，一條命）

首頁右上角按「連線」。**誰都可以開房**，房主選難度和題數（10／15／20／25 題；等人時房主還能改），其他人輸入 4 位數房號（或點邀請連結 `?room=房號`）加入。

- 全部人**同一題、同時作答、同時揭曉**：每個人用自己選的鍵盤（拼音／注音）打；打完只會顯示「已送出，等其他人」，等全部人答完（或時間到）才一起揭曉。
- **一條命**：打錯或時間到，就被雷劈、出局。**有幾個人出局，就落幾道雷**，各自打在那個人身上（小人變黑、眼睛變叉）。
- 出局的人可以**留下來觀賽**；也可以在加入時勾「我只觀賽」。比賽開始後才進來的人，一律觀賽。
- 街上同時有多個小人一起爬，每個人頭上有名字（人多時只顯示前 3～4 個字，完整名字在下方名字列）；自己的小人標紅色。
- 沒人出局的人每題往上一階；爬完全部階梯還活著的人**並列登頂**。全部人同一題出局，就並列第一、直接結束。名次＝撐到第幾階，同階並列。
- 成績**不進排行榜**，只有每一局結束時那張名次表。房主可以按「再來一局」（換新的題目；題數不變，房主可以在等人時再改）。
- 最少 2 位玩家才能開始；房主離開＝關閉整間房；房間 6 小時後自動失效；房主斷線時，其他人約 30 秒後會看到提示，可以自己離開。
- 遊玩紀錄：連線的局數記成 `room-難度-鍵盤`（例如 `room-normal-pinyin`；非 10 題多一段 `-n15` 這樣），後台「遊玩紀錄」分頁看得到。

做法（給之後改程式的人）：房主那台負責推進回合，其他人只寫自己的答題結果，所以不需要另外的伺服器。
- `rayo_rooms/{房號}`：房主寫（難度、題目 `qs`、參賽名單 `ro`、第幾題 `rd`、階段 `ph`＝ready／ask／reveal／end、出局表 `elim`、結果 `final`、局數 `n`）。
- `rayo_rooms/{房號}/players/{uid}`：每個人只寫自己的（名字、角色、是否觀賽、答題結果 `a`：第幾題 → 1 對／0 錯）。
- 時間到沒送出，或離線沒答，一律算答錯。
- 限制：這是朋友／班上用的房間，答題結果由各人的手機自己回報，規則只檢查格式、不檢查答案是否真的打對；15 人上限由程式檢查（規則沒辦法數人數）。

## 登頂慶祝（單機）
答完最後一題走到頂後，鏡頭約 0.9 秒拉近到頂端的人物，人物開心連跳約 3 秒、落彩帶、顯示「登頂！」，然後才跳出結算和排行榜。程式在 `src/template.html` 的 `startCheer` / `zoomTop` / `clearCheer`。

## 空地上的人群與背景音樂（單機）
- **人群**：階梯底下那塊空地站著六排觀看的人（全身背影，共約 120 個，8 種髮型衣服，最前面一排看得到腳），跟著背景一起捲動，所以只有爬到低階、看得到空地時才看得到。人會輕輕晃動，每 0.4 秒有幾個人換成別種背影，做出萬頭鑽動的感覺。程式在 `src/template.html` 的 `buildCrowd` / `layoutCrowd`。
- **背景音樂**：用 Web Audio 現場合成（明快的五聲音階小曲，不用音檔），遊戲進行中才播，暫停、結算、回首頁就停。被雷劈和登頂音效出現時，音樂會先退到後面再慢慢回來（`bgDuck`），不會跟雷聲打架。右上角的靜音鍵會一起關掉。

## 遊玩紀錄

跟所有遊戲一樣用 game-kit 的 `plays.js`，遊戲代號 `rayo`，寫到 memorma 專案：

- `visits`：打開頁面時記一次（每台裝置每天一筆）。
- `plays`：按「開始」記一局，爬完時補上結果（`level` 例如 `normal-pinyin`，非 10 題多一段 `-n15` 這樣、`score` = 答對題數、`secs`、名字）；中途離開的那一局就是「沒玩完」。
- 後台（分享區 stats.html）的「遊玩紀錄」分頁和「排行榜總覽」都看得到。

## 字庫從哪裡來

不另外維護字庫，全部取自 game-kit（你的共用零件 repo）：

- 華語八千詞等級（`bank/vocab_levels.json`）→ 只取單字；
- GoodTeacher 台灣讀音表（`bank/gt/readings.txt`）→ 台灣讀音，多音字只收基本讀音和規則會改成的讀音；
- 沒收錄的單音字用 `pinyin-pro` 補，簡體字用 `opencc-js` 轉。

要改字庫，請改 game-kit 的資料，再重新執行下面的「重新產生」。

## 重新產生（改了程式或字庫才需要）

`index.html` 是自動組出來的：`src/template.html`（遊戲本體）＋ game-kit 的共用零件（靜音鍵、版權小字、遊玩紀錄等）＋ 字庫 ＋ 程式畫的人物和街景（背景一共 7 個台灣場景：九份（`tools/world.js`）＋ 象山看台北 101、中正紀念堂、龍山寺、阿里山檜木棧道、猴硐貓村、夜市天橋（`tools/scenes/*.js`，共用的小工具在 `lib.js`）。除了夜市之外，圖上都不放文字。每一局隨機換（連兩局不會一樣）；連線時由「房號＋第幾局」算出同一個背景，所以全房間看到的一樣，不需要多存任何資料）。背景是「從最底下往上爬」的長圖（480 寬，高度隨題數變）：`tools/tall.js` 把橫式場景（剛好 10 階）上方拉長、中段（第 7～2 階，5 階高）依題數重複貼（階梯接得上；10／15／20／25 題各貼 0／1／2／3 次）、最底下接一段地面，存成 `bg/svg/*.svg`（原始檔，遊戲不讀），再用 `tools/raster.py` 轉成 `bg/*.webp`（遊戲實際載入，共 7 場景 × 4 種題數；檔名帶內容碼，改圖後手機不會讀到舊的；每個場景的地面顏色等微調放在 `tools/tall_opts.js`）。長圖做好後，`tools/detail.js` 會再蓋一層「細節層」：階梯每階的陰影、兩側暗角、石面斑點和裂痕，地面磚縫與水窪，越高越多的霧氣，光暈（燈籠、招牌）、光線、飄動的小粒子（落葉、火星）、飛鳥、線香煙，中段每重複一次光影略不同（打散重複感），以及整體色調和暗角；每個場景要哪些、多少，在 `tools/tall_opts.js` 的 `fx` 設定。細節層都畫在階梯左右或半透明，不會蓋住階梯位置。遊戲裡 `measure()`／`camTo()`／`footPos()`（`src/template.html`）負責把「第幾階」換算成畫面位置，連線的小人、雷擊也都用它。轉圖需要電腦有 python3、playwright、Pillow。`index.html` 只記檔名，所以網頁本身很小；推上去時 `bg/` 一定要一起推。所以重新組檔時，需要電腦上有 **game-kit 資料夾**（預設放在 `/home/claude/game-kit`，放別處就用 `GAMEKIT=資料夾路徑` 告訴它）。平常只是玩遊戲、或只改 `index.html` 以外的說明文字，完全用不到。

```
npm install
node tools/build_words.js   # 產生 data/words.json（讀 game-kit 的字庫）
node tools/build.js         # 產生 index.html（改了 src/template.html 一定要跑）
python3 tests/test_game.py          # 遊戲自動測試（Playwright + Chromium）
python3 tests/test_leaderboard.py   # 排行榜＋遊玩紀錄測試（假的 Firebase，不連網）
python3 tests/test_multi.py         # 連線模式測試（多個瀏覽器分頁＋假資料庫＋規則的 Python 版，約 3 分鐘）
```
